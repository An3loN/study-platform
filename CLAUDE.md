# Study Platform — заметки для Claude Code

Платформа занятий репетитора с учениками: уроки, домашние задания и совместная
доска (Excalidraw поверх Yjs) с курсорами участников.

## Архитектура

| Сервис | Что делает | Порт |
|---|---|---|
| `nginx` | единая точка входа, проксирует всё остальное | 8000 (dev), 80 (prod) |
| `frontend` | React 18 + Vite; в dev — dev-сервер, в prod — статика в своём nginx | 5173 / 80 |
| `backend` | Django 5.1 + DRF, ASGI под daphne | 8000 |
| `hocuspocus` | Node-сервер совместного редактирования Yjs | 1234 |
| `postgres` | БД | 5432 |
| `redis` | Celery (db 1), Hocuspocus (db 2) | 6379 |

Ключевые связи:

- **Доска.** Клиент ↔ `hocuspocus` по WS `/board`. Hocuspocus дёргает Django
  по HTTP: `validate-access/` при подключении, `yjs-state/` на загрузку и
  сохранение. Секрет между ними — `HOCUSPOCUS_SECRET` в заголовке
  `X-Hocuspocus-Secret`.
- **Присутствие.** Курсоры, имена и состав комнаты — awareness Yjs, тем же
  соединением, что и доска. Отдельного WS у Django больше нет.
- **Гостевой вход.** `/j/<share_token>` выдаёт JWT с `guest: true` и `room_id`,
  действует 12 часов; его принимает доска через `validate-access/`.

## Запуск

```bash
cp .env.example .env   # SECRET_KEY и HOCUSPOCUS_SECRET заменить на свои
docker compose -f docker-compose.dev.yml up -d --build
```

Открывать `http://localhost:8000` — всё ходит через nginx. Прямые порты
`8080` (Django) и `1234` (Hocuspocus) открыты только для отладки.

`.env` в git не хранится: после клона на новой машине его нужно создать
из `.env.example`, иначе `config('SECRET_KEY')` уронит Django на старте.

## Что осознанно отложено

1. **Celery без задач.** `config/celery.py` заведён, воркер стартует, но ни одной
   задачи ещё нет. Кандидаты остались только внешние: напоминания об уроке
   (`Lesson.scheduled_at`) и письма вне HTTP-цикла. Автозавершение урока и
   чистка картинок обошлись без него — см. ниже.
2. **Уведомления.** Нужны: о начале урока, за 60 минут до него, об отмене и об
   изменении времени. Это и есть первые настоящие задачи для Celery — отмена
   уже фиксируется в модели (`cancelled_at`, `cancelled_by`, `cancel_reason`),
   так что событие, на которое реагировать, готово.
3. **Планирование.** Ученик должен видеть загруженность преподавателя, чтобы
   выбирать время нового урока, не переспрашивая. Нужен публичный для учеников
   срез занятых интервалов — без тем и имён других учеников.
4. **Тесты есть во всех трёх сервисах.**
   Закрыты статус урока и фильтры, промежуток `?from=&to=`, права и поля
   урока, сроки заданий, адресаты, сдача и приёмка, ветки обсуждения, сводка
   успеваемости, вход и учётные записи, карточка ученика, ссылки с гостевым
   входом, контракт с Hocuspocus; на фронте — перехватчики `api.ts`, маска
   телефона, `lessonTitle` с календарными помощниками, лента «требуют
   внимания», `Modal`, `LessonCard`, `WeekCalendar`. В `hocuspocus` тестов
   свои — `cleanup.ts` и `api.ts`. Сквозные лежат в `e2e/` и запускаются отдельно — образ Playwright
   весит три с половиной гигабайта, поэтому он вынесен в
   `docker-compose.e2e.yml` и в разработке не тянется; порядок запуска —
   в `e2e/README.md`. Запуск: `pytest` в контейнере backend, `npm test`
   во frontend.
5. **Брокер сообщений.** Обсуждали RabbitMQ: для текущего масштаба Redis как
   брокер Celery достаточен. Осмысленный кейс для AMQP — прямой обмен
   `hocuspocus` (Node) ↔ Django вместо HTTP-вызова `saveYjsState`, с durable
   queue и dead-letter вместо потери доски.

## Известные риски, ещё не закрытые

- **Тени удалённых элементов копятся в `Y.Map`.** Осознанно: это небольшой JSON,
  а их вычистка может воскресить элемент у клиента, который переподключится со
  старой копией. Тяжёлое — тела картинок — теперь убирается (см. ниже).

## Что уже починено (не «регрессить» обратно)

- Чат и весь WS-слой Django удалены: приложение `notifications`, `channels`,
  `channels-redis`, `CHANNEL_LAYERS`, `location /ws/` в nginx, прокси `/ws`
  в Vite. Состав комнаты показывает сама доска — источником стал awareness,
  тот же, что рисует курсоры. Redis остался под Celery и Hocuspocus, db 0
  больше не используется. Заодно ушёл единственный JWT в query string.
- **Статус урока вычисляется из времени** (`Lesson.status` — свойство, не
  колонка): до `scheduled_at` «запланирован», до `scheduled_at + duration`
  «идёт», дальше «завершён». Урок без даты всегда «запланирован», без
  длительности считается часовым (`DEFAULT_DURATION_MINUTES`). Кнопок
  «Начать»/«Завершить» и эндпоинтов `/start/`, `/finish/` больше нет.
  Фильтры `?upcoming` и `?past` считают то же самое выражением в SQL: имя
  аннотации `ends_at_db`, потому что одноимённое свойство модели доступно
  только на чтение и Django падает, пытаясь его присвоить.
- **Доска не запирается никогда.** `readonly` убран из `WhiteboardRoom` совсем:
  при вычисляемом статусе затянувшийся урок иначе блокировал бы доску прямо
  посреди занятия. По той же причине снята проверка «урок завершён» на входе
  по ссылке — доступом управляет срок жизни ссылки.
- **Картинки без ссылок убираются из документа** в `onStoreDocument`
  (`hocuspocus/src/cleanup.ts`) — когда от комнаты отключился последний клиент.
  Это единственный безопасный момент: сразу при удалении файл выбрасывать
  нельзя (Ctrl+Z вернёт элемент, один `fileId` делят копии, отставший участник
  может ещё ссылаться), а отложенная задача Celery затёрлась бы сохранением
  Hocuspocus, который держит документ в памяти.
- **Домашние задания: срок, приёмка, обсуждение.** Срок можно задать вручную;
  пустой `due_at` означает «до следующего урока» и считается на лету, поэтому
  перенос занятия двигает срок вместе с собой. Отметка ученика и приёмка
  преподавателя — разные поля `HomeworkSubmission`: «я сделал» не то же самое,
  что «принято». Требование поправок снимает отметку, ученик ставит её заново.
  Оценка необязательна: принять без балла — нормальный исход. Прежний M2M
  `completed_by` перенесён в сдачи миграцией 0007 — данные не потеряны.
- **Задание не обязано быть привязано к уроку.** `Homework.lesson` может быть
  пустым — задать что-то можно и между занятиями. Отсюда два поля: `teacher`
  хранится всегда (по нему проверяются права, выводить его из урока больше
  нельзя), а `students` заполняется только у заданий без урока. Пока урок
  есть, адресаты берутся из него — иначе добавленный на занятие ученик
  перестал бы видеть домашку. Что из двух в силе, решает `Homework.student_set`;
  все проверки идут через него и через `Homework.is_participant`, а не через
  урок. Срок «до следующего урока» у задания без урока считается от момента
  выдачи. Создаётся такое задание через `POST /api/homework/` со списком
  `students` (только свои ученики); `POST /api/lessons/<id>/homework/`
  по-прежнему берёт адресатов из урока и список игнорирует.
  Интерфейс — `HomeworkForm`, кнопка «Создать дз» на главной преподавателя
  и на странице ученика.
- **Обсуждение — по ветке на ученика, не на задание.** `HomeworkMessage.student`
  это не автор, а чья ветка: у сообщения ученика совпадает с автором, у
  сообщения преподавателя указывает адресата. Разбор чужой работы
  одноклассникам видеть незачем. Пустой `student` бывает только у сообщений
  до миграции 0008 — адресата у них задним числом нет, поэтому их видно
  во всех ветках. Отдельного хранилища для сданной работы нет: работа ученика
  это файлы из его ветки, сериализатор собирает их в `submission.files`.
  По той же причине ученику отдаётся только своя строка в `submissions`
  и счёт сообщений только своей ветки.
- **Задание открывается окном поверх страницы.** В панели — короткая карточка
  (о чём, как идёт, до когда), всё остальное в окне: условия, работы всех
  учеников с приёмкой и оценкой, переписка по каждой. В 360 px панели это не
  помещается, а урезать разбор до панели значит его потерять. Окно уходит
  порталом в `body`: панель обрезает всё, что вылезает за её границы.
  Строки сдачи достраиваются на лету для тех, кто ничего не присылал, —
  «не сдал» это тоже состояние, и показать его надо. С главной задание
  открывается тем же окном, а не переходом на урок: идут за работами и
  перепиской, а не за доской, — да и урока у задания может не быть вовсе.
- **Заметки прошлых занятий.** На странице урока преподаватель видит заметки
  с трёх последних уроков — и с доской, и без неё, потому что живут они внутри
  самой панели заметок. Берутся уроки с теми же учениками и только те, где
  заметки непустые: пустая строка в списке ничего не говорит, а место занимает.
  Ученику поле не отдаётся вовсе.
- **Очный урок — без доски.** Флаг `Lesson.has_whiteboard`, по умолчанию
  включён. Выключенная доска убирает и вход по ссылке: она ведёт именно на
  доску, заходить некуда — `share_url` и `share_token` не отдаются вовсе,
  публичные эндпоинты отвечают 404, а `validate-access/` — 403. Проверка там
  стоит до разбора токена: гостевой мог быть выдан ещё до выключения доски и
  живёт 12 часов. На странице урока вместо доски показываются те же панели
  заметок и ДЗ, но сразу и колонкой — прятать их за корешками незачем, кроме
  них на странице ничего нет.
- **Отмена урока.** Отменить может и преподаватель, и ученик — причина
  обязательна, её видит вторая сторона. Отмена перебивает вычисляемый статус:
  отменённый урок не «идёт» и не «завершается». Из списка урок не пропадает —
  остаётся с причиной и приглушённой карточкой. Удалить урок насовсем может
  только преподаватель, там же в меню. Обратной операции нет: снять отмену
  сейчас нельзя, только удалить и создать заново.
- **Вход и регистрация — по макету «Мати».** Клетчатый лист, карточка по
  центру, математические знаки по углам (`AuthPage`, `.auth-*`). Поля собраны
  в `components/UI/Field` — подпись, рамка с иконкой, подсказка снизу; рамку
  держит обёртка, иначе иконку внутрь не поставить, а фокус ловится через
  `:focus-within`. Восстановления пароля нет и не планируется: сбрасывает
  преподаватель, об этом прямо сказано на экране.
- **Телефон вводится в маске `+7 999 000-00-00`** (`utils/phone.ts`). Код
  страны поле рисует само, поэтому значение никогда не пустое — «введён ли
  номер» проверяет `isPhoneComplete`, а не `required`. Номер, набранный или
  вставленный целиком («8999…», «+7999…»), распознаётся по лишней цифре и
  код отбрасывается; обрезать хвост нельзя — в маске потерю не заметить.
  Следствие: номер не из российского плана нумерации ввести теперь нельзя.
- **Как устроены тесты.** Бэкенд — `pytest` + `pytest-django`, общие фикстуры
  («преподаватель, его ученики, чужой преподаватель», `make_lesson`,
  `make_homework`) в корневом `backend/conftest.py`. Настройки берутся из
  `config.settings.test` через `addopts = "--ds=..."`, а не через ini-опцию:
  в образе выставлена переменная `DJANGO_SETTINGS_MODULE=config.settings.dev`,
  и она перебила бы ini — тесты молча шли бы с debug-toolbar. Клиент у каждой
  роли свой (`as_teacher`, `as_student`, `as_stranger`): на общем объекте
  второй `force_authenticate` молча перебивает первый. Время подменяется
  `time-machine`, и всегда с `tick=False` — с идущими часами проверки границ
  становятся гонкой. Фронт — `vitest` с отдельным `vitest.config.ts`, чтобы
  не тянуть плагин копирования ассетов Excalidraw на каждый запуск. В
  `hocuspocus` — тоже `vitest`, HTTP перехватывается `nock`. Паузы между
  повторами сохранения там ждутся честно: подменённые таймеры прокручиваются
  раньше, чем перехваченный запрос отвечает, и пауза зависает. Тесты
  исключены из `tsconfig.json` и `.dockerignore` — иначе `npm run build`
  тащил бы их в `dist`, а прод-образ вместе с ними.
- **Прод и выкладка.** CI — GitLab на своём раннере, отдельной машине: на
  прод-сервере с двумя гигабайтами сборка фронтенда не влезает и утащила бы за
  собой работающие контейнеры. Образы уезжают в реестр проекта (job-токен, без
  отдельных учётных данных), сервер забирает их deploy-токеном с правом только
  на чтение. У всех джоб стоит тег `study-platform`: без совпадения они уедут
  на общие раннеры gitlab.com и съедят бесплатные минуты, ради экономии которых
  свой раннер и заводился. Выкладка — ручная джоба, её запускает человек. У сервисов в `docker-compose.yml` указаны и
  `image`, и `build` — на сервере работает `pull`, локально тем же файлом
  собирается прод-стек для проверки; адрес реестра приходит переменной
  `REGISTRY_IMAGE`, без неё имена образов остаются локальными. Тег образа
  задаётся `IMAGE_TAG`, поэтому откат — это повтор `deploy.sh` с прежним sha.
  В джобе тестов бэкенда перечислены `SECRET_KEY` и `HOCUSPOCUS_SECRET`: без
  `.env` их неоткуда взять, а значения по умолчанию у них в `base.py`
  отсутствуют намеренно — Django падает на импорте настроек ещё до тестов.
- **TLS: nginx плюс отдельный certbot.** Домен подставляется в конфиг через
  `APP_DOMAIN` при старте контейнера (`nginx/templates`, фильтр envsubst по
  префиксу `APP_` — иначе он съел бы `$http_host` и прочие переменные самого
  nginx). Курица и яйцо решена заглушкой: если сертификата нет, entrypoint
  кладёт самоподписанный, nginx поднимается, и ACME-проверка получает ответ.
  `SECURE_SSL_REDIRECT` стал управляться переменной по той же причине — на
  первом запуске редирект Django отправлял бы по кругу саму проверку. nginx
  перечитывает конфигурацию раз в шесть часов: certbot меняет файл в общем
  томе, а nginx держит открытым старый.
- **Celery в проде не поднимается** — он под compose-профилем. Задач у него
  по-прежнему ни одной, а воркер съедал бы около трёхсот мегабайт из двух
  гигабайт. Появятся задачи — `docker compose --profile celery up -d`.
- **Мёртвый код вычищен.** Приложения `apps.courses` больше нет: `Lesson`
  намеренно не привязан ни к курсу, ни к теме, `apps.courses.urls` так и не
  подключили, а во фронтенде курсов не было ни разу — при этом таблицы
  создавались. `WhiteboardSnapshot` тоже удалён: это был предыдущий подход к
  сохранению доски, актуальный механизм — `WhiteboardYjsState`, а вьюха
  `/<lesson_pk>/snapshot/` не вызывалась ниоткуда. Таблицы курсов сносит
  `common/0002_drop_courses` — миграция лежит в чужом приложении именно
  потому, что вместе с `courses` исчезли и его собственные миграции, и на
  машине с уже созданными таблицами удалять их было бы нечем; там же
  чистятся осиротевшие contenttypes и права.
- **`username` убран совсем, логин — телефон.** Раньше `USERNAME_FIELD` не
  переопределяли, а username генерировали мусором (`student-3f2a91c8b4`),
  из-за чего админский поиск по `teacher__username` искал по этому мусору.
  Теперь `username = None`, `USERNAME_FIELD = 'phone'` и свой
  `PhoneUserManager`: базовый `UserManager` требует username первым
  аргументом и ронял бы `createsuperuser`. `User.clean()` переопределён —
  `AbstractBaseUser.clean()` прогоняет USERNAME_FIELD через
  `normalize_username`, и у ученика без телефона `None` стал бы строкой
  «None», а двое таких столкнулись бы на unique. Наборы полей в админке
  заданы целиком, а не достроены к `UserAdmin.fieldsets`: базовые начинаются
  с несуществующего поля.
- **Успеваемость ученика считает сервер.** `GET /api/students/<id>/stats/` —
  средняя, распределение оценок, сдача в срок и последние три месяца по всей
  истории. На фронте это собиралось из выдачи списка, а та пагинирована по
  20: цифры молча считались по первой странице и выглядели достоверно. Срок
  «до следующего урока» там же считается без запроса на каждое задание —
  времена уроков берутся один раз, ближайшее следующее ищется двоичным
  поиском.
- **Заметки урока приходят со списком.** `notes` есть и в
  `LessonListSerializer` (по-прежнему только преподавателю). Страница ученика
  показывает их прямо в ленте уроков и раньше добирала каждый урок отдельным
  запросом — до двадцати лишних на страницу.
- **Главные страницы и карточка ученика — по макету «Мати».** У преподавателя:
  сводка плитками, календарь недели, лента заданий «требуют внимания» и
  список учеников с поиском. У ученика: идущий урок плашкой, тот же календарь
  и задания по статусам. Карточка ученика открывается по клику из списка —
  приглашение с QR у незарегистрированных, статистика, настройки. Навигации
  в шапке нет намеренно: страниц, между которыми ходить, всего три, и на
  каждую есть прямой путь с главной — шапка держит логотип, пользователя и
  «Выйти». `teacher_name` в списке уроков и `?student=` в списке заданий
  добавлены под эти экраны.
- **Названия у урока нет — подписывают участники.** Поле `Lesson.title` из
  формы убрано: на каждое занятие с одним и тем же учеником его заполняли бы
  одинаково. Вместо него `lessonTitle(lesson, selfId)` собирает подпись из
  имён, причём своё имя смотрящий в ней не читает: преподаватель видит
  учеников, ученик — преподавателя и одноклассников, гость по ссылке —
  преподавателя, потому что состава ему не отдают вовсе. Строка под названием
  в карточке урока освободилась — там были ровно те же имена, осталась только
  причина отмены. Колонка `title` в базе жива, и `lessonTitle` по-прежнему
  предпочитает её: у уроков, созданных когда тему заполняли, названия на
  месте, а форма шлёт PATCH без этого поля и потому их не затирает. Сносить
  колонку — только вместе с решением, что тема не нужна и в админке.
- **Календарь грузит неделю одним запросом.** `?from=&to=` в списке уроков
  (`WeekCalendar`): перелистывание дней внутри недели тогда не ходит на
  сервер, а число уроков в дне известно заранее — по нему рисуется пометка
  загруженности. Границы дня фронт считает по местному времени и шлёт полным
  ISO со смещением; на бэкенде `parse_moment` принимает и дату, и момент.
  Иначе на границе суток уроки уезжали бы в соседний день.
- **Настройки ученика у преподавателя.** `User.default_lesson_duration` —
  сколько длится урок именно с этим учеником, подставляется в форму нового
  урока с его карточки; пусто — общее `Lesson.DEFAULT_DURATION_MINUTES`.
  Там же преподаватель задаёт пароль: write-only поле в `StudentSerializer`,
  через `set_password` и с валидаторами Django. Это единственный способ
  восстановить доступ — своего сброса у ученика нет.
- **«Отправить» и «Обновить ссылку» в карточке приглашения не сделаны.**
  Отправлять нечем: канала рассылки нет вообще. Перевыпуска приглашения тоже
  нет — среди `invite_urlpatterns` только info, accept и qr. Осталась
  «Копировать». Первая кнопка упирается в уведомления, вторая — небольшой
  отдельный эндпоинт.
- **Сроки ссылок.** `apps.common.SiteSettings` — одна строка настроек в админке:
  приглашение 7 дней, ссылка на урок 2 дня. У приглашения срок стамповится при
  выдаче в `expires_at` (иначе уменьшение настройки погасило бы разосланное).
  У урока считается от конца занятия и потому не хранится — перенос урока
  двигает срок вместе с собой; `share_expires_at` остаётся ручным перекрытием.
  Истёкшая ссылка отвечает 410 с пояснением, а не 404.
- Прод-образ `hocuspocus` не собирался вовсе: `npm ci --omit=dev` не ставил
  `typescript`, которым выполняется `npm run build`, а `tsconfig` с `module:
  Node16` без `"type": "module"` в `package.json` ругался на ESM-импорты.

- `libpq-dev` и `gcc` убраны из обоих backend-Dockerfile: зависимости —
  `psycopg2-binary` и `Pillow`, ставятся готовыми wheel-ами. Этот apt-слой
  занимал больше времени, чем вся остальная сборка.
- `RUN collectstatic` убран из `backend/Dockerfile`: prod-настройки требуют
  `SECRET_KEY`, а `.env` в build-контекст не попадает (`.dockerignore`) —
  сборка prod-образа падала. Статика собирается в `entrypoint.sh`.
- `frontend/nginx.conf` с `try_files $uri $uri/ /index.html` — без него
  перезагрузка на `/lessons/<id>`, `/invite/<token>`, `/j/<token>` давала 404.
- `npm ci` вместо `npm install` в `frontend/Dockerfile.dev`.
- `config/celery.py` + экспорт `celery_app` в `config/__init__.py`: сервис
  `celery -A config worker` в проде падал с `Unable to load celery application`.
- **401 на логине не идёт через авто-рефреш.** Неверный пароль — обычный
  ответ формы, а не протухшая сессия: перехватчик не находил refresh-токен
  (его у невошедшего и нет), чистил `localStorage` и уходил на `/login`
  через `window.location`. Страница перезагружалась целиком и уносила с
  собой сообщение об ошибке вместе с набранным номером. Теперь запрос
  `/auth/login/` обходит эту ветку; для остальных поведение прежнее.
- `token_blacklist` подключён, `BLACKLIST_AFTER_ROTATION = True`: раньше при
  ротации старый refresh оставался валидным все 7 дней.
- `asgi.py` / `wsgi.py` по умолчанию берут `config.settings.prod` — незаданная
  переменная должна ронять запуск, а не поднимать сервер с `DEBUG=True`.
- debug-toolbar показывается через `SHOW_TOOLBAR_CALLBACK`: проверка по
  `INTERNAL_IPS` за nginx не срабатывала никогда.
- `YjsStateView.get` отдаёт 404 при отсутствии состояния — контракт, который
  `hocuspocus/src/api.ts` и так ожидал.
- `saveYjsState` повторяет попытки на сетевых и 5xx ошибках и логирует потерю;
  раньше один неудачный PUT молча стирал доску за весь урок.
- `REDIS_PORT` добавлен в `.env.example` — его читает `hocuspocus/src/server.ts`.
- `location /static/` добавлен в `nginx/nginx.dev.conf`: без него статика админки
  и debug-toolbar уходила в `location /` на Vite и возвращалась как `index.html`.
  В prod-конфиге `/static/` уже отдавался из общего volume.
- `__debug__` убран из prod-конфига nginx.
- Гостевая сессия переживает перезагрузку страницы: она лежит в `sessionStorage`
  под ключом share-токена (`utils/guestSession.ts`), при восстановлении
  проверяется `exp` токена. Не `localStorage`: временный токен на комнату не
  должен оставаться после закрытия вкладки. Данные урока в шапке берутся из
  свежего `shareInfo`, а не из сохранённой сессии — статус мог смениться.
  Сменить имя раньше можно было через F5, поэтому добавлена кнопка «Выйти».

### Доска

- **Курсоры и имена участников** — через awareness Yjs (`provider.awareness`), а не
  через документ: presence эфемерен, в БД ему делать нечего. Excalidraw получает
  их как `collaborators` в `updateScene`.
- **Лазерная указка** едет тем же каналом: `pointer.tool === 'laser'`. Excalidraw
  рисует чужой след только при `button === 'down'`, поэтому смена состояния
  кнопки идёт мимо throttle — иначе след не начинается или не обрывается.
- **Undo больше не стирает чужое.** Excalidraw откатывает сцену целиком и всё,
  чего нет в снимке истории, помечает удалённым с ПОВЫШЕННОЙ версией — от
  обычного удаления это не отличить по версиям. Поэтому: помечаем сам факт
  undo (Ctrl+Z/Y по `event.code` и кнопки тулбара), а при отправке не публикуем
  откат чужих элементов и возвращаем их из документа с версией выше обеих.
  «Свой» — только тот элемент, который в документ внесли мы: если считать своим
  всё однажды отправленное, чужое попадает в свои и защита не срабатывает.
- **Раскладка.** Excalidraw читает `event.key`, поэтому на кириллице шорткаты
  не работали. Подменяем событие на латинский аналог по `event.code`; в полях
  ввода и текстовом редакторе доски подмена отключена.
- **Колесо мыши масштабирует без Ctrl** — событие пересылается с `ctrlKey: true`.
  Shift оставлен горизонтальной прокрутке.
- **Толщина линии — слайдер** (1..12). Он встроен порталом в секцию «Stroke width»
  левой панели Excalidraw (`.Island.App-menu__left`), рядом с остальными
  свойствами инструмента, и показывается **только для карандаша**: у фигур
  остаётся штатный выбор из трёх значений, поэтому CSS прячет его через
  `.wb-stroke-slider` — класс висит на обёртке только когда активен карандаш.
  У ластика левой панели в Excalidraw 0.17 нет вовсе, встроить туда нечего.
  Слайдер меняет и значение по умолчанию, и выделенные элементы.
- **Своё присутствие не отдаётся в сцену.** `setAwarenessField` вызывается на
  каждое движение мыши, а awareness сообщает об изменении и своего клиента —
  без фильтра Excalidraw получал `setState` на каждую точку штриха.

## Соглашения

- Комментарии и интерфейс — на русском.
- Панели боковой вкладки урока размонтируются, когда вкладку скрывают:
  `LessonSidebar` рисует только активную. Поэтому копировать данные из пропсов
  в состояние один раз при монтировании нельзя — надо синхронизировать
  эффектом, иначе после «скрыл и открыл» на экране окажется состояние на
  момент открытия страницы.
- API отдаёт snake_case, фронт работает с camelCase; конвертация — в
  интерцепторах `frontend/src/services/api.ts`, компоненты о snake_case не знают.
- Ответы DRF пагинированы (`PAGE_SIZE = 20`), фронт ждёт `Paginated<T>`.
- `.gitattributes` нормализует переводы строк в LF: `entrypoint.sh` с CRLF
  в контейнере не запустится.

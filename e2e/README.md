# Сквозные тесты

Идут по живому стеку через nginx — той же дверью, что и браузер. Логику они не
проверяют, на неё есть модульные тесты; здесь проверяется, что слои сходятся:
nginx пропускает, фронт доходит до API, API отвечает тем, что фронт умеет читать.

## Запуск

Стек должен быть уже поднят (`docker-compose.dev.yml`).

```bash
docker compose -f docker-compose.dev.yml exec backend python manage.py e2e_seed
docker compose -f docker-compose.dev.yml -f docker-compose.e2e.yml run --rm e2e
docker compose -f docker-compose.dev.yml exec backend python manage.py e2e_purge
```

`e2e_seed` заводит преподавателя `+70000000001`: через API его создать нельзя —
своего маршрута регистрации у преподавателя нет и не будет. Учеников, уроки и
задания каждый тест создаёт себе сам и за собой убирает, поэтому данные
разработки не задеваются. `e2e_purge` убирает преподавателя вместе с тем, что
могло остаться после упавшего прогона.

Обе команды отказываются работать при `DEBUG=False`.

## Почему отдельный compose-файл

Образ Playwright весит около трёх с половиной гигабайт в распакованном виде.
Тянуть его на каждой машине ради разработки незачем — он нужен только тому,
кто запускает эти тесты.

## Vite и заголовок Host

Внутри docker-сети до приложения ходят по адресу `http://nginx`, и nginx
передаёт `Host` как есть. Dev-сервер Vite такой хост по умолчанию отклоняет,
поэтому в `frontend/vite.config.ts` он добавлен в `server.allowedHosts`.
Снаружи dev-сервер не опубликован — открыт только порт nginx.
